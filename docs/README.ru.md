# ShapeHatch — генератор моделей для 3D-печати

Создание брелка по изображению или многоцветной плашки с надписью. Реальный размер в миллиметрах, 3D-просмотр, экспорт STL/3MF.

## Установка и обновление

ShapeHatch состоит из двух сервисов: **`web`** (Nginx, интерфейс и прокси
`/api/`) и **`api`** (FastAPI, генерация моделей). По умолчанию приложение
доступно на **порту 8086**. Серверные проекты сохраняются в постоянном
Docker-томе, а локальные копии — в браузере.

### Способ 1. Docker Compose — сборка из исходников

Нужны Docker Engine, плагин Docker Compose v2 и Git. На Docker-хосте:

```bash
git clone https://github.com/mirivlad/ShapeHatch.git
cd ShapeHatch
docker compose up -d --build
docker compose ps
```

После запуска откройте `http://localhost:8086` на самом Docker-хосте или
`http://IP_СЕРВЕРА:8086` с другого компьютера. Проверка API:

```bash
curl -fsS http://localhost:8086/api/health
```

Порт для этого способа задаётся в **`compose.yaml`**, в строке `8086:80`
(слева — порт хоста). Для другого порта, например 8090, измените её на
`8090:80` и пересоздайте контейнеры командой `docker compose up -d`.
Переменная `SHAPEHATCH_HTTP_PORT` в **этом** файле не используется.

Обновление установленной версии:

```bash
cd ShapeHatch
git pull --ff-only
docker compose up -d --build
```

Логи и остановка:

```bash
docker compose logs --tail=100 api web
docker compose down
```

Обычный `down` сохраняет том с проектами. **Не запускайте**
`docker compose down -v`, если не собираетесь удалить базу сохранённых моделей.

### Способ 2. Portainer — готовые образы из GHCR

Для этого способа **не нужно** клонировать репозиторий, устанавливать Git на
Docker-хосте или собирать приложение. Нужны Portainer с подключённым Docker
и доступ к GitHub / `ghcr.io`. Готовые образы сейчас публикуются для
**linux/amd64**.

1. Откройте **Stacks → Add stack → Repository** (Git repository).
2. Укажите имя стека: **`shapehatch`**.
3. Repository URL: `https://github.com/mirivlad/ShapeHatch`.
4. Repository reference: `refs/heads/main`.
5. Compose path: **`portainer-stack.yml`**, не `compose.yaml`.
6. При необходимости добавьте переменную окружения
   `SHAPEHATCH_HTTP_PORT=8090` (без неё используется 8086).
7. Нажмите **Deploy the stack**, проверьте статус контейнеров `web` и `api`.
   Откройте `http://IP_DOCKER_ХОСТА:8086` (либо выбранный порт) и
   `http://IP_DOCKER_ХОСТА:8086/api/health`.

Используются готовые образы `ghcr.io/mirivlad/shapehatch-web:latest` и
`ghcr.io/mirivlad/shapehatch-api:latest`. Для **публичных** GHCR-пакетов
токен не нужен.

Обновление: дождитесь успешного завершения GitHub Actions
**Publish Docker images** для `main`, затем в Portainer откройте
**Stacks → shapehatch → Pull and redeploy**, при наличии включите
повторное скачивание образов (re-pull). Простой Restart без скачивания
новых образов версию не обновляет.

Подробности: [инструкция для Portainer](PORTAINER.md).

### Сохранённые проекты и безопасность

В обоих вариантах серверная база находится по пути `/data/gallery.sqlite3`
в API-контейнере и подключается через именованный том `gallery-data`.
Фактическое имя Docker-тома обычно содержит префикс проекта или стека;
найдите его в **Portainer → Volumes** или командой `docker volume ls`.
Том **сохраняется** при обновлении или пересоздании контейнеров, пока его
не удаляют отдельно. Делайте резервные копии: для работающей базы SQLite
нужна согласованная копия (либо перед обычным копированием остановите API).

Локальные проекты в IndexedDB не исчезают при временной недоступности
сервера. Старые локальные проекты можно вручную перенести на сервер через
галерею. Ключ восстановления из 64 символов необходимо сохранить отдельно:
он даёт полный доступ к галерее, и у сервиса пока нет учётных записей или
восстановления забытого ключа.

По умолчанию веб-порт опубликован на всех интерфейсах Docker-хоста.
**Для доступа из интернета нужны HTTPS, контроль доступа и ограничения
частоты запросов.** Не публикуйте тестовую версию напрямую наружу.

## Генераторы

**Силуэты:** импорт PNG/JPG/WebP/SVG, распознавание замкнутого внешнего контура
(в том числе на рисунках из тонких линий), отдельное управление внутренними контурами,
сглаживание, ширина, толщина, плоская петелька или выступающий из края
закруглённый столбик с поперечным отверстием.

**Таблички (текст или картинка):** пошаговый редактор с возвратом к ранее выполненным
шагам без потери параметров. Текст — обычная надпись с рельефом или вставкой.
Для картинки порядок такой: **тип содержимого → основа и её размеры →
загрузка, подгонка и перемещение картинки → палитра и дизеринг → крепление → экспорт**.
Подгонка может быть целиком, с заполнением/обрезкой, по ширине, по высоте
или вручную. Масштаб, координаты X/Y и толщина цветного слоя (0,2–2 мм)
настраиваются отдельно от детализации растра. Области рисунка, выступающие
за край таблички, обрезаются.

Доступны подбор 2–16 цветов (Авто для логотипов, сохранение исходной палитры,
ближайшие цвета, Median Cut, K-Means), необязательные режимы дизеринга
Floyd–Steinberg, Atkinson и Bayer, реальные цвета катушек, ручная замена
цветов и предварительный просмотр до/после. Если исходник уже содержит
не более заданного количества цветов, **переквантование пропускается**.
Режим логотипа предпочитает чёткие границы; фото обрабатываются со
сглаживанием. Режим «исходная палитра» сообщает об ошибке, если число
цветов превышает лимит.
Все цветные элементы строятся отдельными печатаемыми объёмами снизу (Z=0);
основа располагается выше. При создании объёмов изображение автоматически
зеркалится по горизонтали в координатах принтера: готовая деталь после
снятия со стола и переворота лицевой стороной вверх отображает рисунок
в исходной ориентации. 2D-оптимизация не зеркалится, вид «Снизу» показывает
готовую лицевую сторону. В слайсере модель оставляют лицом вниз без
дополнительного зеркалирования.

**Надписи:** пять форм основы; 12 шрифтов с кириллицей: DejaVu (4 варианта), Russo One, Play Bold, PT Sans, Lobster, Rubik Mono One, Unbounded, Comfortaa, Terminus TTF; многострочный текст, размер, глубина, цвет; выпуклый текст, гравировка и цветная вставка; сквозное отверстие, плоская петелька или столбик с поперечным отверстием.

**Общие крепления для табличек и силуэтов:** нет крепления, отверстие,
петелька в плоскости, столбик с поперечным отверстием или магниты.
До восьми открытых карманов под круглые/прямоугольные магниты, отдельное
позиционирование в мм или перетаскиванием сиреневых маркеров, глубина,
посадочный допуск и проверка стенок. Карманы на обратной стороне: у
картинок — сверху, у текста и силуэтов — снизу. Магниты после печати
вклеиваются; закрытые полости для закладки магнитов ещё не реализованы.

**Просмотр:** мышью вращать, масштабировать и сдвигать; кнопки видов и навигационный кубик. Когда включено крепление, перетащите бирюзовую точку по 3D-сцене: она автоматически прилипает к ближайшей точке внешнего контура. Точные координаты магнитов задаются численно. На изображениях с несколькими отдельными фрагментами используется контур самого большого фрагмента. Для табличек оранжевая ручка в середине текстовой области позволяет перемещать надпись по плоскости (X/Y в миллиметрах). Если текст не помещается, экспорт блокируется до исправления параметров.

**Экспорт:** 3MF с отдельными цветными частями (назначьте пластики в слайсере), простой STL и ZIP с отдельными STL, импортируемыми как составной объект.

## Внутренние контуры и скругление верхней кромки

После загрузки изображения выберите **«Внутренние контуры»**. Каждый замкнутый
внутренний элемент можно выделить непосредственно на модели или в списке.
Для каждого элемента выбирается действие:

- **Тот же материал** — внутреннюю область заполняет основной пластик.
- **Другой материал / цвет** — верхний слой является отдельной цветной
  вставкой (глубина вставки регулируется), а снизу остаётся сплошная основа.
  Цветные части сохраняют общие координаты в 3MF и STL ZIP.
- **Оставить пустым** — сквозное отверстие через всю толщину.

По умолчанию в режиме «Залитый силуэт» внутренние участки заполняются, в
режиме «Силуэт с отверстиями» становятся вырезами. Для рисунка тонкими
замкнутыми линиями удобен режим «Залитый силуэт» или «Контурный рисунок» —
редактор определит внешний контур и отдельные элементы внутри него.
Незамкнутые штрихи и открытые линии не могут служить внутренними вырезами:
изображение необходимо предварительно замкнуть.

В обоих генераторах раздел «Размеры» / «Основа» содержит параметр
**«Скругление верхней кромки, мм»**. По умолчанию **0,3 мм**, допустимый
диапазон **0–0,4 мм** (ноль отключает скругление). Кромка строится геометрически
в STL и 3MF; дно модели остаётся плоским. На очень тонких элементах
фактический радиус может быть уменьшен, чтобы сохранить замкнутость сетки.
Для цветной вставки/гравировки переходы между цветами и текстом
остаются вертикальными.

## Настройки редактора

Генераторы используют пошаговый мастер с кнопками «Назад»/«Далее»: пять шагов для силуэтов и текстовых табличек, шесть для табличек с картинкой.
Можно напрямую переходить к любому предыдущему шагу, не теряя введённые
параметры. Контуры, геометрия текста, полигоны картинки и экструзии
кэшируются по собственным зависимостям: неизменённые объёмы не перестраиваются.
 Размеры отверстия и стенки крепления сохраняются в localStorage браузера и автоматически подставляются в новые проекты обоих генераторов. Настройки уже сохранённых проектов остаются независимыми.

Восемь новых TTF-файлов распространяются по лицензии SIL OFL 1.1. Источники и копии лицензий приведены в [списке шрифтов](../backend/fonts/README.md). Перед печатью особенно проверяйте мелкие штрихи шрифта Terminus.

## Галерея

Начиная с 0.4.0, при нажатии **«Сохранить проект»** полный проект (включая исходную
картинку и все настройки) сохраняется в локальной IndexedDB и в SQLite на сервере.
В **«Моей галерее»** проект можно повторно скачать как 3MF, открыть и отредактировать.
Старые локальные проекты по-прежнему видны; для переноса на сервер у них есть
отдельная кнопка.

Регистрации нет: браузер создаёт случайный **ключ доступа из 64 шестнадцатеричных
символов**. Для работы на другом устройстве нужно скопировать его в галерее
на старом устройстве и восстановить галерею по ключу на новом. Храните ключ как
пароль! Любой, кто его знает, сможет получить и удалить ваши проекты. При
потере ключа и данных браузера восстановить личную галерею нельзя.

Архив на сервере хранится в постоянном Docker-томе `gallery-data`
(`/data/gallery.sqlite3` в API-контейнере). Не удаляйте этот том при обновлении,
делайте его резервные копии. Ограничения: 100 проектов и 80 МБ на галерею,
9 МБ на проект, 500 МБ на всё хранилище. Перед публичным открытием
рекомендуются HTTPS, ограничения запросов и дальнейшее усиление защиты от злоупотреблений.

## Толщина изделия и крепление

При выборе столбика с поперечным отверстием толщина брелка или таблички автоматически подгоняется под его наружный диаметр: **диаметр отверстия + 2 × толщина стенки**. Столбик выходит из края модели, отверстие смотрит вбок, а не в сторону лицевой поверхности. При смене режима обычное значение толщины сохраняется. Проверьте модель в слайсере и убедитесь, что выбранная толщина подходит для изделия.

## Ограничения

- Не гарантирована печатаемость при любом размере: слишком тонкие элементы могут сломаться.
- Контуры внутри силуэта должны быть замкнутыми. Следите за выбором режима распознавания и порога на некачественных сканах.
- Положение текста можно менять мышью на сцене или вручную через X/Y в миллиметрах. Несколько независимых текстовых блоков пока не поддерживаются.
- В 3MF исправлены пространства имён материалов по спецификации 3MF Core; названия и цвета записываются для каждого составного объекта. Сопоставление с реальными катушками/слотами AMS зависит от конкретного слайсера, и его необходимо проверить перед печатью. Вариант экспорта **3MF Anycubic / Orca** дополнительно записывает назначения филаментов и палитру в метаданные Orca/Anycubic Slicer Next. Это экспериментальная функция, требующая проверки в реальном слайсере; номер слота и профиль принтера необходимо подтвердить перед печатью. Обычный стандартный 3MF сохраняется отдельно.
- Для фото с большим количеством мелких цветовых островков снизьте детализацию до 24–48 пикселей по длинной стороне. Иначе модель может быть слишком сложной.
- Для магнитных карманов минимальная оставляемая толщина основы составляет 0,6 мм, а отступ от наружного края — 0,8 мм.
- SVG с внешними ресурсами и скриптами отклоняются.

## Ввод числовых параметров (0.4.1)

Все числовые поля (в том числе координаты X/Y магнитов) позволяют полностью стереть старое значение, ввести отрицательное число и использовать как точку, так и запятую для дробной части. Изменения применяются по мере ввода корректного числа; Enter и выход из поля завершают ввод. Стрелки вверх/вниз меняют значение с заданным шагом.
