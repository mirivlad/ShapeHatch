# ShapeHatch — установка и обновление через Portainer

[Основной README](../README.md) · [Документация на русском](README.ru.md)

Этот способ подходит для Docker-хоста с Portainer: **сборка исходников не нужна**.
Portainer загружает опубликованные в GitHub Container Registry (GHCR)
контейнеры из `portainer-stack.yml`, а не из `compose.yaml`.

## Что будет установлено

| Сервис | Образ | Назначение |
| --- | --- | --- |
| `web` | `ghcr.io/mirivlad/shapehatch-web:latest` | Интерфейс на Nginx и прокси запросов `/api/` |
| `api` | `ghcr.io/mirivlad/shapehatch-api:latest` | FastAPI и генерация моделей |
| `gallery-data` | Именованный Docker-том | SQLite с сохранёнными проектами |

Готовые образы публикуются сейчас только для **linux/amd64**.
Публичные образы GHCR можно скачать **без GitHub PAT**. Нужен доступ
Docker-хоста/Portainer к `github.com` и `ghcr.io`.

Веб-интерфейс публикуется по HTTP на порту **8086**. Отдельно открывать
порт 8000 для API не нужно: Nginx направляет запросы к API внутри
Docker-сети.

## Развёртывание из Git-репозитория

1. Выберите в Portainer нужное Docker-окружение.
2. Откройте **Stacks → Add stack → Repository** (Git repository).
3. Заполните параметры:
   - **Name:** `shapehatch`
   - **Repository URL:** `https://github.com/mirivlad/ShapeHatch`
   - **Repository reference:** `refs/heads/main`
   - **Compose path:** `portainer-stack.yml`
4. При необходимости в **Environment variables** добавьте
   `SHAPEHATCH_HTTP_PORT` со значением `8090` (или вашим свободным портом).
   Если переменную не добавлять, будет опубликован порт 8086.
5. Нажмите **Deploy the stack** и убедитесь, что оба сервиса, `api` и
   `web`, запущены. Первый запуск включает скачивание образов.
6. Откройте в браузере `http://IP_DOCKER_ХОСТА:8086`
   (или порт из переменной) и проверьте
   `http://IP_DOCKER_ХОСТА:8086/api/health`.
   Успешный ответ имеет вид `{"ok":true,"version":"0.5.0"}`
   (номер версии будет отличаться в новых релизах).

**Важно:** путь к Compose-файлу именно `portainer-stack.yml`.
Файл `compose.yaml` предназначен для сборки из исходников,
и его не следует выбирать при установке готовых образов.

## Обновление приложения

Публикация изменений в `main` запускает GitHub Actions
**Publish Docker images**. В нём сначала выполняются тесты и
только затем публикуются оба образа с тегами `latest` и
`sha-<полный SHA коммита>`.

1. Убедитесь, что workflow **[Publish Docker images](https://github.com/mirivlad/ShapeHatch/actions/workflows/docker-publish.yml)**
   завершился успешно **для нужного коммита**.
2. В Portainer откройте **Stacks → shapehatch** и выберите
   **Pull and redeploy** (название может зависеть от версии Portainer).
3. Если Portainer предлагает **Re-pull image / Pull latest images**,
   включите эту опцию. Подтвердите обновление стека.
4. Проверьте `/api/health`, интерфейс и доступность ранее сохранённых
   проектов.

Стек с `pull_policy: always` скачивает новые версии образов при
повторном развёртывании. **Просто Restart контейнеров не обновляет образ.**
Локальная сборка и `docker compose build` для этого способа не нужны.

## Где лежат проекты, как их сохранить

Начиная с ShapeHatch 0.4.0, серверная галерея хранится в SQLite:
`/data/gallery.sqlite3` внутри контейнера `api`. Каталог `/data`
подключён из именованного Docker-тома **`gallery-data`**.

При развёртывании через Portainer фактическое имя тома, как правило,
будет **`shapehatch_gallery-data`** (префикс зависит от имени стека).
Проверяйте фактическое имя через **Volumes** в Portainer или
`docker volume ls` на Docker-хосте. При обычном обновлении или
пересоздании контейнеров этот том сохраняется. Если переименовать стек,
Compose может создать **другой** том с новым префиксом, и старые проекты
не появятся автоматически — это не означает, что старый том удалился.

- **Не удаляйте том** при обновлении или удалении стека. Удаление тома
  уничтожит серверные копии проектов.
- Делайте резервные копии. Для работающей SQLite-базы используйте её
  штатный механизм согласованного резервного копирования либо остановите
  `api` перед копированием файла базы. Не рассчитывайте на простое
  копирование работающего файла SQLite.
- Ключ восстановления галереи (64 символа) хранится у пользователя.
  Он даёт полный доступ к его проектам на сервере. Сохраните его в
  надёжном месте: при потере ключа и данных браузера штатного способа
  восстановления нет.
- Проекты, сохранённые только в браузере в старых версиях, можно
  перенести на сервер через **«Мою галерею»**.

## Настройки сети и безопасность

По умолчанию публикация порта `8086:80` доступна на **всех**
сетевых интерфейсах Docker-хоста. Для размещения в интернете
используйте HTTPS через обратный прокси и ограничения доступа/частоты
запросов. Сейчас у ShapeHatch нет учётных записей, а галерея
защищается только ключом доступа. Не выставляйте тестовый сервис
напрямую в интернет без дополнительных мер защиты.

Переменная `SHAPEHATCH_HTTP_PORT` предусмотрена **только**
в `portainer-stack.yml`. В обычном Compose-варианте хостовый порт
меняется в секции `ports` файла `compose.yaml`.

## Диагностика

- **Нет доступа к сайту:** проверьте `web` и `api` в разделе
  **Containers**, сетевые правила, порт и отсутствие конфликтов
  с другим сервисом.
- **Ошибка при загрузке образа:** проверьте успешную публикацию в
  GitHub Actions, доступность GHCR и архитектуру `linux/amd64`.
  Для публичных образов реестр с PAT не нужен.
- **Сайт старой версии после redeploy:** убедитесь, что скачан именно
  новый digest `latest`, а не просто перезапущен старый контейнер.
  Версию backend можно узнать через `/api/health`.
- **Ошибка галереи:** проверьте наличие тома `gallery-data`,
  доступность каталога `/data` для API и логи контейнера `api`.
  Ключи восстановления двух браузеров должны совпадать, чтобы
  увидеть одни и те же серверные проекты.
- **Логи:** откройте **Containers → соответствующий контейнер → Logs**.
  Имена контейнеров могут отличаться в зависимости от названия стека.
- **Порт занят:** поменяйте `SHAPEHATCH_HTTP_PORT` в настройках
  стека и выполните redeploy.
